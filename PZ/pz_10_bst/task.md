## Теоретические сведения

С развитием компьютерной техники проблема хранения и обработки больших объемов данных становилась все более актуальной. Возникла необходимость организации хранилища для больших объемов данных, которое предоставляет возможность быстро находить и модифицировать данные. Один из способов организации такого хранилища — бинарные (двоичные) деревья поиска, представляющие собой графы. Эту структуру данных можно описать на любом языке программирования, в котором есть составные типы данных (списки, кортежи, множества, словари и т.д.).

### 1. Граф

* **Граф** — структура, модель, описывающая объекты и связи между ними.
* **Граф** — набор узлов (вершин) и ребер, через которые связаны узлы.
* **Неориентированный граф (неоргаф)** — граф, ни одному ребру которого не присвоено направление.
* **Ориентированный граф (оргаф)** — граф, ребрам которого присвоено направление. Направленные ребра именуются также дугами.
* **Связный граф** — граф, в котором существует путь между любыми двумя вершинами.
* **Путь** — последовательность вершин $x_1, x_2, x_3, \dots, x_k$, в которой каждая пара вершин $(x_i, x_{i+1})$, $i = 1, 2, \dots, k-1$ является ребром, причем все эти ребра различны. Путь соединяет вершины $x_1$ и $x_k$.
* **Длина пути** — число ребер в пути, то есть $k-1$.
* **Цикл** — замкнутый путь, у которого $x_1 = x_k$.

### 2. Дерево

* **Дерево** — связный неориентированный граф без циклов (ациклический), содержащий более 2 вершин.
* Любое дерево — граф. Не любой граф — дерево.
* **Корень** — узел, находящийся на самом верхнем уровне (не являющийся чьим-либо потомком; узел с минимальным порядковым номером).
* **Листья (висячие вершины)** — узлы, не имеющие потомков (оба потомка которых равны `NULL`/`None`). Вершины, которым инцидентно лишь одно ребро.
* Если в графе есть ребро $(a, b)$, то говорят, что вершины $a$ и $b$ в нем смежны. Ребро $e = (a, b)$ инцидентно каждой из вершин $a$ и $b$.
* **Корневое дерево** — дерево, в котором задан корень (дерево ориентировано сверху вниз от самой верхней вершины).

### 3. Бинарное дерево

* **Бинарное дерево (Двоичное дерево)** — древовидная структура данных, в которой каждый узел имеет не более двух дочерних узлов, называемых левым и правым потомком.
* **Бинарное дерево** — рекурсивная структура данных, состоящая из корня, левого поддерева и правого поддерева.
* **Уровень вершины (узла)** — длина пути от корня дерева до данной вершины. Корень имеет уровень 0.
* **Высота дерева** — наибольшее число ребер от корня до самого дальнего листового узла (величина, равная максимальному из уровней вершин).
* **Глубина дерева (количество уровней)** — число вершин, которые лежат на максимальной ветви от корня к листьям.
* **Поддерево** — дерево, содержащее часть вершин главного дерева, причем корнем поддерева может быть любая вершина главного дерева.

### 4. Бинарное дерево поиска

**Бинарное дерево поиска (Binary Search Tree, BST)** — бинарное дерево, обладающее свойством упорядоченности ключей для каждого узла:
* все узлы левого поддерева содержат значения (ключи), меньшие значения в данном узле;
* все узлы правого поддерева содержат значения (ключи), большие значения в данном узле.

Для типа ключей должна быть определена операция строгого линейного порядка (сравнения на меньше/больше).

#### 4.1. Виды сбалансированных бинарных деревьев поиска:
1. Идеально сбалансированное бинарное дерево поиска (число узлов в левом и правом поддеревьях любого узла различается не более чем на 1).
2. АВЛ-деревья (по фамилиям Г.М. Адельсон-Вельского и Е.М. Ландиса).
3. Красно-черные деревья.
4. Самоперестраивающиеся деревья (splay-деревья).

Чем меньше высота бинарного дерева поиска, тем быстрее осуществляются операции. В сбалансированном дереве высота $h \sim O(\log n)$, в вырожденном (несбалансированном) дерево превращается в связный список высотой $h \sim O(n)$.

#### 4.2. Поиск узла в бинарном дереве поиска
Значение искомого ключа сравнивается со значением ключа в текущем узле (начиная с корня):
* если ключ меньше ключа узла — переходим в левое поддерево;
* если ключ больше ключа узла — переходим в правое поддерево;
* если ключ равен значению узла — узел найден;
* если достигнута пустая ссылка (`None`), искомого ключа в дереве нет.

Количество шагов ограничено высотой дерева: $O(h)$.

#### 4.3. Вставка узла в бинарное дерево поиска
* **Предшественник узла $A$** — узел, содержащий наибольшее значение, меньшее значения узла $A$ (максимум левого поддерева).
* **Последователь узла $A$** — узел, содержащий наименьшее значение, большее значения узла $A$ (самый левый узел правого поддерева).
  * Если правое поддерево узла $A$ не пустое, то последователь — это узел с минимальным значением в правом поддереве.
  * Если правое поддерево пустое, последователь ищется подъемом вверх к предкам до первого узла, для которого текущая ветвь является левой.

Для вставки нового узла выполняется спуск от корня по правилам поиска до обнаружения пустой позиции, куда и прикрепляется новый лист.

#### 4.4. Удаление узла из бинарного дерева поиска
При удалении узла возможны 3 ситуации:
1. **Узел листовой (нет потомков):** узел удаляется, соответствующая ссылка у его родителя обнуляется (`None`).
2. **Узел имеет 1 потомка:** узел удаляется, а его единственный потомок связывается напрямую с родителем удаляемого узла.
3. **Узел имеет 2 потомков:** удаляемый узел заменяется своим последователем (минимальным узлом из правого поддерева). Значение последователя копируется в удаляемый узел, после чего сам последователь удаляется из правого поддерева (по случаю 1 или 2).

### 5. Реализация бинарного дерева поиска в Python

```python
class BTree:
    def __init__(self, value=None, link_left=None, link_right=None, link_parent=None):
        self.value = value
        self.link_left = link_left
        self.link_right = link_right
        self.link_parent = link_parent

    def search(self, value_search):
        node = self
        while node is not None and value_search != node.value:
            if value_search < node.value:
                node = node.link_left
            else:
                node = node.link_right
        return node
```

## Теоретические сведения

### 1. Стратегия «Разделяй и властвуй»

Алгоритмы «разделяй и властвуй» (*Divide-and-conquer algorithms*) — рекурсивные алгоритмы, использующие стратегию декомпозиции задачи на независимые подзадачи (рекурсивно реализованный алгоритм бинарного поиска, алгоритм быстрой сортировки, алгоритм сортировки слиянием и др.).

«Разделяй и властвуй» — подход к решению задачи.

Стратегия «разделяй и властвуй» включает 2 этапа:
1. **Определить базовый случай** как простейший случай из всех возможных.
2. **Придумать способ**, как свести задачу к базовому случаю (например, путем деления или сокращения).

*Пример базового случая:* при написании рекурсивной функции, в которой задействован массив, базовым случаем часто оказывается пустой массив `[]` или массив из одного элемента `[x]`.

---

### 2. Быстрая сортировка

Быстрая сортировка (*Quicksort*) — рекурсивный алгоритм сортировки, в котором базовым случаем является массив размером 0 или 1 и который состоит из трех этапов:
1. Выбрать опорный элемент (*pivot*) в массиве.
2. Разделить массив на два подмассива так, чтобы в одном подмассиве были элементы, меньшие опорного (или равные опорному), а в другом — элементы, большие опорного (для этого необходимо осуществить проход по элементам массива и совершать перестановки элементов).  
   В результате исходный массив разделяется на 3 части:
   - подмассив всех элементов, меньших опорного;
   - опорный элемент;
   - подмассив всех элементов, больших опорного.
3. Рекурсивно применить быструю сортировку к двум подмассивам.

* Временная сложность алгоритма в худшем случае: $O(n^2)$.
* Временная сложность алгоритма в среднем случае: $O(n \log n)$.
* Временная сложность алгоритма в лучшем случае: $O(n \log n)$.

#### Схема разбиения при выборе последнего элемента в качестве опорного:
```text
Исходный:  [4, 0, 3, 7, 1, 5, 3, 2]  (опорный = 2)
Разбиение: [1, 0]  +  [2]  +  [7, 3, 5, 3, 4]
            ├── [0, 1]         ├── [3, 3] + [4] + [5, 7]
Итог:      [0, 1, 2, 3, 3, 4, 5, 7]
```

Быстрая сортировка — один из самых быстрых существующих алгоритмов сортировки. Особенность алгоритма в том, что добиться времени выполнения в среднем и лучшем случае достаточно легко:
* Если при выборе опорного элемента будет всегда выбираться **первый** (или последний) элемент, то на упорядоченных данных алгоритм деградирует до худшего сценария — $O(n^2)$.
* Если опорный элемент выбирается **случайным образом**, алгоритм демонстрирует устойчивую среднюю производительность — $O(n \log n)$.
* Если опорный элемент делит массив строго пополам (**медиана/средний элемент**), алгоритм выполняется по лучшему сценарию — $O(n \log n)$.

### 3. Сортировка слиянием

Сортировка слиянием (*Merge sort*) — разделение массива на подмассивы (вплоть до единичных) с последующим слиянием соседних подмассивов с одновременным упорядочиванием.

**Этапы алгоритма сортировки слиянием:**
1. Разбиение массива на две части примерно одинакового размера.
2. Сортировка каждой части массива (рекурсивное применение).
3. Соединение отсортированных подмассивов в один результирующий массив:
   - поэтапное попарное сравнение элементов из двух подмассивов и перенос наименьшего из них в итоговый массив;
   - когда один из подмассивов исчерпан — простое добавление остатка второго подмассива в конец.

* Временная сложность алгоритма (все случаи: лучший, средний, худший): $O(n \log n)$.

#### Схема рекурсивного деления и слияния:
```text
               [13, 37, 95, 18,  4, 25,  8]
               /                          \
       [13, 37, 95, 18]               [4, 25, 8]
        /            \                 /       \
    [13, 37]      [95, 18]          [4, 25]    [8]
    /     \       /      \          /     \     │
  [13]   [37]   [95]    [18]       [4]   [25]  [8]
    \     /       \      /          \     /     │
    [13, 37]      [18, 95]          [4, 25]    [8]
        \            /                 \       /
       [13, 18, 37, 95]               [4, 8, 25]
               \                          /
               [4, 8, 13, 18, 25, 37, 95]
```

#### Таблица 1. Временная сложность алгоритмов поиска и сортировки

| Алгоритм | Лучший случай | Средний случай | Худший случай |
| :--- | :---: | :---: | :---: |
| **Линейный поиск** | $O(1)$ | $O(n)$ | $O(n)$ |
| **Бинарный поиск** | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| **Сортировка выбором** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| **Сортировка пузырьком** | $O(n)$ | $O(n^2)$ | $O(n^2)$ |
| **Быстрая сортировка** | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| **Сортировка слиянием** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ |

---

### 4. Константы в нотации «О-большое»

Время выполнения алгоритма по нотации «О-большое» может содержать константу, которая обозначается буквой $c$:
$$O(c \cdot n)$$
Константа $c$ может быть равна произвольному числу.

* Если для двух алгоритмов порядок роста времени разный, например $O(n)$ и $O(n^2)$, то константа несущественно влияет на асимптотику (при больших $n$), поэтому она не учитывается и опускается.
* Если для двух алгоритмов время выполнения одинаковое, например $O(n \log n)$, константа имеет решающее практическое значение.

У быстрой сортировки скрытая константа меньше, чем у сортировки слиянием. Поэтому, несмотря на идентичную оценку $O(n \log n)$, быстрая сортировка на практике работает быстрее. Кроме того, средний случай быстрой сортировки встречается значительно чаще худшего.

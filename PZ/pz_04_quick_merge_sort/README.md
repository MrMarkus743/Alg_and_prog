# Practical Work 04: Quick Sort and Merge Sort

## Overview

Практическая работа посвящена исследованию рекурсивной стратегии «Разделяй и властвуй» (Divide and Conquer), реализации и анализу вычислительной сложности алгоритмов быстрой сортировки (Quicksort) и сортировки слиянием (Merge Sort), оценке роли скрытых констант в $O$-нотации, а также решению оптимизационной задачи сортировки массива по модулю за линейное время $O(n)$.

---

## Solutions & Theoretical Analysis

### Задача № 1. Определение О-большого для базовых операций

1. **Вывод значения каждого элемента массива:**
   - Алгоритм проходит по массиву один раз и выполняет $n$ операций вывода.
   - **Сложность:** $O(n)$ (линейная).

2. **Удвоение значения каждого элемента массива:**
   - Для каждого из $n$ элементов выполняется ровно одна арифметическая операция умножения.
   - **Сложность:** $O(n)$ (линейная).

3. **Удвоение значения только первого элемента массива:**
   - Доступ по фиксированному нулевому индексу `arr[0]` выполняется мгновенно и не зависит от размера массива $n$.
   - **Сложность:** $O(1)$ (константная).

4. **Создание таблицы умножения для всех элементов массива:**
   - Каждое число из $n$ элементов умножается поочередно на все остальные $n$ чисел (два вложенных цикла). Общее число операций: $n \times n = n^2$.
   - **Сложность:** $O(n^2)$ (квадратичная).

### Задача № 2. Рекурсивный подсчет элементов в списке

Базовый случай — пустой список `arr == []`, возвращается `0`. В рекурсивном случае длина текущего среза выражается как $1 + \text{recursive\_count}(arr[1:])$.
```python
def recursive_count(arr):
    if not arr:
        return 0
    return 1 + recursive_count(arr[1:])
```
Временная сложность: $O(n)$, пространственная сложность по стеку вызовов: $O(n)$.

---

### Задача № 3. Рекурсивный поиск наибольшего числа в списке

Базовый случай — список из одного элемента `len(arr) == 1`, возвращается само значение `arr[0]`. При большем размере текущий элемент сравнивается с максимумом остатка списка.
```python
def recursive_max(arr):
    if len(arr) == 1:
        return arr[0]
    sub_max = recursive_max(arr[1:])
    return arr[0] if arr[0] > sub_max else sub_max
```
Для массива варианта № 1 `[45, 67, 79, 40, 40, 23, 15, 29, 47]` функция возвращает `79`.

### Задача № 4. Схема рекурсии и стек вызовов

#### 1. Дерево вызовов Quick Sort для массива `[4, 0, 3, 7, 1]` (опорный — последний элемент)

```text
[4, 0, 3, 7, 1]  (pivot = 1)
 ├── Меньше: [0] (базовый случай, возврат [0])
 ├── Равно:  [1]
 └── Больше: [4, 3, 7]  (pivot = 7)
              ├── Меньше: [4, 3]  (pivot = 3)
              │            ├── Меньше: []
              │            ├── Равно:  [3]
              │            └── Больше: [4]
              │            └── Итог ветки: [3, 4]
              ├── Равно:  [7]
              └── Больше: []
              └── Итог ветки: [3, 4, 7]
Результат: [0] + [1] + [3, 4, 7] = [0, 1, 3, 4, 7]
```

#### 2. Трассировка стека вызовов для правой ветки Quick Sort:

| Уровень стека | Входной подмассив | Опорный элемент | Результат этапа |
| :---: | :---: | :---: | :---: |
| 3 | `[4]` | `4` | `[4]` |
| 2 | `[4, 3]` | `3` | `[3, 4]` |
| 1 | `[4, 3, 7]` | `7` | `[3, 4, 7]` |
| 0 | `[4, 0, 3, 7, 1]` | `1` | `[0, 1, 3, 4, 7]` |

#### 3. Схема слияния Merge Sort для массива `[13, 37, 95, 18]`:

```text
               Разделение: [13, 37, 95, 18]
               /                          \
           [13, 37]                    [95, 18]
          /        \                  /        \
        [13]      [37]              [95]      [18]
          \        /                  \        /
       Слияние: [13, 37]           Слияние: [18, 95]
               \                          /
             Итоговое слияние: [13, 18, 37, 95]
```

* **Случайный выбор опорного элемента (`random`):** гарантирует время $O(n \log n)$ с вероятностью, близкой к 1, и исключает худший случай $O(n^2)$ на уже отсортированных последовательностях.

### Задача № 6. Оптимальная сортировка отсортированного массива по модулю

#### Постановка задачи:
Дан отсортированный массив, содержащий отрицательные и положительные числа, например:
`arr = [-12, -7, -3, 0, 2, 5, 9, 15]`. Необходимо упорядочить его по возрастанию абсолютных значений.

#### Анализ вариантов реализации:
1. **Наивный подход:** взять модуль от всех чисел `[abs(x) for x in arr]` и отсортировать заново через Quick Sort или Timsort.  
   *Сложность:* $O(n \log n)$. Не учитывает исходную упорядоченность данных.
2. **Оптимальный подход (Метод двух указателей / Two Pointers):**  
   Так как исходный массив уже отсортирован, самые большие по модулю элементы гарантированно находятся либо в самом начале (наибольшие по модулю отрицательные числа), либо в самом конце (наибольшие положительные числа).  
   Мы ставим указатели `left = 0` и `right = n - 1`, сравниваем `abs(arr[left])` и `abs(arr[right])` и заполняем результирующий массив с конца:
   * Если `abs(arr[left]) > abs(arr[right])`, записываем `abs(arr[left])` и сдвигаем `left += 1`.
   * Иначе записываем `abs(arr[right])` и сдвигаем `right -= 1`.

#### Вывод:
Метод двух указателей решает задачу строго за **$O(n)$ по времени** и **$O(1)$ по дополнительной памяти** (не считая результирующего массива), что асимптотически эффективнее любого алгоритма сортировки сравнениями.

# Practical Work 07: Hash Tables and Applications

## Overview

Практическая работа посвящена исследованию принципов функционирования хеш-таблиц, методам борьбы с коллизиями, контролю коэффициента заполнения (Load Factor), криптографическому хешированию с солью, а также реализации собственной хеш-таблицы на массиве из 20 ячеек с алгоритмом открытой адресации (Linear Probing).

---

## Solutions & Theoretical Analysis

### 1. Архитектура хеш-таблицы и разрешение коллизий

* **Временная сложность:**
  - В среднем случае: вставка, удаление и поиск выполняются за **$O(1)$** благодаря прямому преобразованию ключа в индекс массива через хеш-функцию.
  - В худшем случае (при высокой скученности коллизий): деградация до **$O(n)$**.
* **Коэффициент заполнения (Load Factor):**
  $$\text{Load Factor} = \frac{n}{N}$$
  Отражает степень загруженности таблицы. При превышении порога $0.7$ вероятность возникновения длинных цепочек пробирования резко возрастает, требуя рехеширования в массив удвоенного размера.

### 2. Разбор решений практических задач

#### Задача № 1. Безопасная вставка
Реализована функция `safe_insert(hash_table, key, value)`, проверяющая наличие ключа через оператор `in` за $O(1)$ и предотвращающая перезапись существующих данных.

#### Задачи № 2 и № 3. Дедупликация файлов по хешу содержимого
Сравнение файлов по имени не гарантирует идентичности содержимого. Функция `get_file_hash()` рассчитывает контрольную сумму MD5 блоками по 4 КБ.
* **Задача 2:** Сканирует директорию `Директория_1`, группирует имена файлов по одинаковому хешу и возвращает группы дубликатов.
* **Задача 3:** Принимает произвольный внешний файл и находит его дубликат в целевой папке независимо от имени файла.

#### Задачи № 4 и № 5. Хеширование паролей и система авторизации
* **Соление паролей:** добавление случайной последовательности символов к паролю блокирует атаки по предвычисленным словарям (Rainbow Tables).
  - *Статическая соль:* константная строка, одинаковая для всей системы.
  - *Динамическая соль:* генерируется индивидуально для каждого пользователя через криптостойкий генератор `secrets.token_hex(8)` и сохраняется рядом с хешем.
* **Авторизация:** Класс `AuthSystem` хранит словарь учетных записей `login -> {hash, salt}`. При входе хеш введенного пароля вычисляется с сохраненной солью пользователя.

#### Задача № 6. Собственная хеш-таблица на массиве ($N = 20$)
Таблица реализована без использования встроенного словаря Python:
* **Хеш-функция:** `hash(key) = len(key) % 20`.
* **Разрешение коллизий:** метод открытой адресации (линейное пробирование: при занятости ячейки проверяется `(idx + 1) % 20`).
* **Удаление:** ячейка помечается служебным маркером `"<DELETED>"`, что позволяет цепочкам пробирования продолжать поиск и повторно использовать ячейку при новых вставках.

#### Расчет Load Factor (Задача № 6):
1. **Пункт А:** Загрузка 15 продуктов в массив емкостью 20 ячеек:
   $$\text{Load Factor} = \frac{15}{20} = 0.75$$
2. **Пункт Б:** Последовательное удаление 4 продуктов (`Орехи грецкие`, `Водоросли`, `Специи`, `Манго`):
   $$\text{Load Factor} = \frac{15 - 4}{20} = \frac{11}{20} = 0.55$$

# Practical Work 06: Linked Lists and Queue Applications

## Overview

Практическая работа посвящена проектированию и программной реализации динамических структур данных на языке Python: однонаправленного (Singly), двунаправленного (Doubly) и циклического (Circular) связных списков. На основе однонаправленного списка реализована структура данных «Очередь» (FIFO) с константным временем вставки и удаления $O(1)$, а также смоделирована система распределения и обработки 20 заявок пулом параллельных обработчиков с разной производительностью.

## Solutions & Theoretical Analysis

### 1. Сравнительный анализ: Массив vs Связный список

| Параметр | Массив (`list` в Python) | Связный список (`Node`) |
| :--- | :--- | :--- |
| **Физическое размещение** | Непрерывный блок адресов в RAM | Разрозненные узлы в куче, связанные ссылками |
| **Доступ к элементу (`Read / Search`)** | $O(1)$ по индексу через смещение | $O(n)$ последовательным проходом от `head` |
| **Вставка в начало (`Prepend`)** | $O(n)$ из-за сдвига ссылок массива | $O(1)$ сменой ссылки `head` |
| **Вставка в конец (`Append`)** | $O(1)$ амортизированное | $O(1)$ при наличии указателя `tail`, иначе $O(n)$ |
| **Удаление из начала (`Pop First`)** | $O(n)$ | $O(1)$ смещением головы |
| **Накладные расходы по памяти** | Минимальные (массив указателей) | Дополнительные байты на каждый объект узла и ссылки |

### 2. Реализованные структуры данных

#### 1. Однонаправленный связный список (`SinglyLinkedList`)
Каждый узел содержит поле значения `value` и одну прямую ссылку `link_next`.
* Вставка в начало (`prepend`) и удаление из начала (`pop_first`): строго $O(1)$.
* Поиск по значению (`find`), вставка в произвольное место и удаление по значению: $O(n)$.

#### 2. Двунаправленный связный список (`DoublyLinkedList`)
Каждый узел содержит ссылки в двух направлениях: `link_next` и `link_prev`.
* Позволяет выполнять двунаправленный обход.
* Удаление заданного узла выполняется за $O(1)$ при наличии ссылки на узел, так как нет необходимости искать его предшественника перебором с начала списка.

#### 3. Циклический связный список (`CircularLinkedList`)
Последний элемент замыкается ссылкой на начальный узел `head` вместо `None`.
* Устраняет необходимость явной проверки на граничный `None` при бесконечных кольцевых буферах или планировщиках задач (Round-Robin).
* При обходе в цикле `display()` используется контрольная проверка возврата к `self.head`.

#### 4. Очередь на базе связного списка (`LinkedQueue`)
Для устранения недостатка стандартного `list.pop(0)` (сложность $O(n)$) очередь построена на базе однонаправленного списка с поддержкой двух указателей:
* `head` — голова очереди (откуда извлекаются элементы за $O(1)$);
* `tail` — хвост очереди (куда добавляются новые элементы за $O(1)$).
Все 4 операции Задачи № 4 (заполнение, извлечение, перенос всех элементов и перенос первых $N$ элементов) работают без обращения по индексу.

### 3. Анализ системы обработки заявок (Задачи № 5* и № 6*)

Поток из 20 заявок распределяется между тремя обработчиками с разным быстродействием:
* **Обработчик 1:** скорость 1.00 сек/заявка;
* **Обработчик 2:** скорость 1.01 сек/заявка;
* **Обработчик 3:** скорость 2.00 сек/заявка.

#### Принцип балансировки:
Каждая новая заявка из очереди направляется тому обработчику, который освободится раньше всех:
$$\text{worker} = \arg\min (\text{busy\_until})$$

#### Результат расчета:
* При параллельной обработке 20 заявок тремя процессорами общее время выполнения пакета задач составило **~8.00 секунд** (вместо ~28 секунд при последовательной обработке на одном воркере).

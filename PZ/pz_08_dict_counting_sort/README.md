## Overview

## Solutions & Theoretical Analysis

### 1. Архитектура словарей в Python и сложность операций

Внутренняя хеш-таблица Python использует схему плотного хранения с открытой адресацией (псевдослучайное пробирование):

| Операция | Синтаксис | Средняя сложность | Худшая сложность | Примечание |
| :--- | :--- | :---: | :---: | :--- |
| **Чтение по ключу** | `d[key]` или `d.get(key)` | $O(1)$ | $O(n)$ | Поиск ячейки по хешу ключа |
| **Запись / Обновление** | `d[key] = value` | $O(1)$ | $O(n)$ | Автоматическое рехеширование при заполнении 2/3 |
| **Проверка наличия** | `key in d` | $O(1)$ | $O(n)$ | Проверка только хеша и ключа, значения не сканируются |
| **Удаление** | `del d[key]` или `d.pop(key)` | $O(1)$ | $O(n)$ | Замена ячейки на служебный маркер Dummy |

### 2. Разбор алгоритма сортировки подсчетом (Counting Sort)

#### Принцип работы:
1. Определяются минимальный $\min(A)$ и максимальный $\max(A)$ элементы входного массива размера $n$.
2. Выделяется вспомогательный массив счётчиков размера $k = \max(A) - \min(A) + 1$.
3. За один линейный проход по массиву $A$ подсчитывается количество каждого элемента: `count[x - min] += 1`.
4. За один проход по массиву `count` формируется итоговая отсортированная последовательность.

#### Анализ асимптотической сложности:
* **Время:** $O(n + k)$, где $n$ — число элементов, $k$ — ширина диапазона значений. Если диапазон $k \le O(n)$, алгоритм работает строго быстрее любой сортировки сравнениями ($O(n \log n)$).
* **Память:** $O(k)$ дополнительной памяти под массив частот.
* **Ограничение классической версии:** Если массив содержит числа `[1, 1000000000]`, обычный массив потребует 1 млрд ячеек памяти. Для разреженных массивов применяется модификация со словарем частот `counting_sort_dict`, расходующая память строго пропорционально количеству уникальных чисел $O(\text{unique})$.

### 3. Алгоритмическая задача: «Шахматные ладьи»

#### Постановка задачи:
Даны координаты $n$ ладей на шахматной доске: $[(r_1, c_1), (r_2, c_2), \dots, (r_n, c_n)]$. Определить, бьют ли какие-либо две ладьи друг друга.

#### Оптимальное решение:
Ладьи угрожают друг другу тогда и только тогда, когда хотя бы у двух ладей совпадает номер строки $r$ или номер столбца $c$.  
* Вместо попарного сравнения каждой ладьи со всеми остальными ($O(n^2)$) координаты заносятся в два частотных словаря `row_counts` и `col_counts` за $O(n)$.
* Если хотя бы одно значение в словарях $> 1$, доска не является безопасной.
* Временная сложность алгоритма — строго **$O(n)$**, дополнительная память — **$O(n)$**.
